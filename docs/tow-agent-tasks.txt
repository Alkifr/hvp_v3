Отвечать пользователю по-русски. Коммиты только по явной просьбе.

Концепт РМ сменился после разговора с бизнесом. Неделя, шкала события и сутки
ангара больше не являются рабочим местом. Их не развивать и не возвращать в интерфейс.
Этот файл — источник правды по новому РМ. В том же дереве есть незавершённые ранее
правки (персонал, дедлайн, цеха, справка). Их не откатывать.


1. Как теперь устроено РМ

Одно окно — реестр. Вкладок «План» / «Реестр» нет. Режимов «Неделя», «Шкала события»
и «Сутки ангара» нет.

Реестр выносит все события Гантта, которые пересекают выбранное окно. Событие
попадает в список, даже если выкатки нет и буксировка ещё не создана. Отменённые
и DELETED скрыты, как бары Ганта. DONE только для просмотра. Рабочий контур:
MaintenanceEvent.sandboxId = null. Песочница идёт заголовком X-Sandbox-Id.

«План» — одна строка на событие. Столбец называется «Буксировка», не «Край».
Новые события сверху. Назначение и правка времени — на плане.
«Реестр» — только уже назначенные буксировки, со столбцами «Примечание»,
«Позиция» и «Причина сдвига начала». Письмо и фиксация версии идут с реестра.

Окно по умолчанию: сегодня 08:00 МСК включительно → завтра 08:00 МСК исключительно.
Пользователь меняет обе границы датой и временем до минуты. Границы не привязаны
к календарной полуночи и не округляются до суток. Событие, которое только
начинается в правой границе 08:00, относится уже к следующим операционным суткам.

На каждом крае кнопка «Буксировка не требуется». Отметка сохраняется. Такой край
не считается ожидающим, в автозаполнение не попадает и в повторном заполнении
не затирается. В снимке и в письме отметка видна явно.

Время края правится в реестре датой и временем до минуты. Это основной способ
поправить автопостановку. Буксировка по-прежнему обязана лежать внутри события.


2. Автопостановка при создании события

В момент создания события края заполняются из справочника нормативов.
Код EDGE_TOW_MINUTES, имя «Буксировка в начале и в конце события», по умолчанию
30 минут. Берётся активная запись справочника, не зашитое число.

Правила planEdgeTows сохраняются:
- закатка: перрон «МС» → стоянка, от начала первого ручного этапа на норматив;
- выкатка: стоянка → «МС», норматив до конца последнего ручного этапа;
- пара на разрыве (AUTO_GAP) крепится к соседним ручным этапам и отдельной
  строкой реестра не становится;
- занятый край и пересекающееся окно не перезаписываются;
- этап короче двух нормативов на одном размещении пропускается, причина пропуска
  остаётся в расчёте.

Точка вызова — POST /api/events, после replaceEventPlacements, в той же транзакции.
Уже существующие события сами не дозаполняются. Импорт, который уже записал свою
буксировку, второй интервал на то же окно не создаёт: planEdgeTows видит занятое
окно. Если у импорта буксировки не было, края ставятся тем же расчётом.

Повторное ручное заполнение краёв, если оно останется в API, не затирает занятый
край и не снимает отметку «не требуется».


3. Фиксация, отправка, журнал версий

Реестр дальше фиксируется и уходит по кнопке. Черновик несохранённой формы
в снимок и в письмо не входит: сначала запись строки, потом фиксация.

Кнопка «Отправить реестр» делает две вещи атомарно с точки зрения пользователя:
пишет версию и отправляет письмо. Версия — снимок всех строк выбранного окна,
включая пустые края и «не требуется». В версии: кто, когда, окно, получатели,
комментарий, строки и значения полей, которые ушли в письмо.

Журнал отправок показывает эти версии. Из журнала можно открыть сравнение двух
версий: добавленные строки, снятые строки, изменённые поля.

Пока пользователь смотрит реестр, строка маркируется относительно последней
отправки, в которую она входила:
- новое событие, которого не было в той версии;
- событие, которое было в версии и исчезло из текущего окна;
- поле, значение которого отличается от снимка.
Маркируется конкретное поле, не вся строка целиком. Несохранённый ввод маркером
версии не является: маркер сравнивает сохранённое состояние с снимком.

Отдельно от журнала отправок фиксируется каждая сохранённая правка строки:
кто, когда, поле, было, стало. Сдвиг начала уже существующей буксировки
по-прежнему требует причину. Без причины API отклоняет. Причина пишется
и в правку, и в поле startChangeReason.

Письмо по-прежнему требует SMTP и право записи. Колонки TOW_EXPORT_COLUMNS
расширяются под строку-событие: оба края, отметка «не требуется», признак
отличия от прошлой версии. Уже созданные интервалы больше не единственное
содержимое письма.


4. Правила, которые нельзя ломать

- Буксировка лежит внутри события. API отклоняет выход за границы.
- Буксировка привязана к placement.
- Закатка: перрон «МС» → стоянка. Выкатка: стоянка → «МС».
- Окончание занятости (occupancyEndAt) отдельно от окончания движения.
- Событие DONE только для просмотра.
- Отменённые и DELETED скрыты.
- Права: tows:read, tows:write. events:write и gantt:write тоже дают запись событий.
  assertCanWriteTow запрещает запись в песочнице только для чтения.
- Время в интерфейсе — МСК, UTC+3, без перехода на летнее время.
- Цвета кнопок сервиса не подменять. Кнопка по умолчанию белая. Главная кнопка #2563eb.
  Вкладки sandboxesTab, активная нижняя граница #2563eb.
  Поля tgField, карточка белая, приглушённый текст #64748b, основной #0f172a.
  Маркер отличия от отправленной версии не красить как красный пустой край.
  Красный #dc2626 остаётся только у края, который ещё не решён: нет буксировки
  и нет отметки «не требуется».


5. Что уже есть и что строить

Уже есть и переиспользуется:
- справочник TowNorm и planEdgeTows;
- POST /api/events/:id/tows и POST /api/events/:id/tows/edges;
- PATCH /api/tows/:id со причиной сдвига начала;
- реестр и письмо towRegistryMail по TOW_EXPORT_COLUMNS;
- POST /api/tows/send — сейчас только письмо, снимок не пишет;
- правка времени в реестре до минут уже есть у интервала, но период задаётся
  календарной датой через startOfMskDayIso / endOfMskDayIso.

Нужно построить:
- реестр строк-событий за окно [from, to) с точностью до минуты;
- период по умолчанию 08:00→08:00 МСК;
- отметку «не требуется» на край;
- автопостановку краёв в POST /api/events;
- снимок версии на отправке и журнал отправок;
- сравнение двух версий;
- маркировку полей, отличающихся от последней отправки этой строки;
- журнал сохранённых правок строки;
- справку HelpView: убрать неделю, шкалу и сутки, описать реестр, отметку,
  автопостановку и журнал.

Проверки, которые уже подключены явными списками:
  cd apps/web && npx tsc -p tsconfig.json --noEmit --pretty false
  cd apps/web && node --import tsx --test src/lib/towPlanGeometry.test.ts
Тесты API: towBoard, towRegistryMail, edgeTows в apps/api/package.json.
Новые правила окна, снимка и маркировки покрыть своими тестами рядом с этими.
